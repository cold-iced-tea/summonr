# Working with bounded intelligence

Summonr connects interactive exploration, repeatable procedures, persistent collaborators, and evidence-producing systems through a common execution model.

| [Research and laboratories](laboratories.md) | Collect specimens, construct tests, assay behavior, and package findings |

## From an experiment to a system

Begin by extracting checked fields from a document. Package the procedure as a capability another agent calls. Measure it against labeled cases. Let a director select it using those measurements. Apply the same context machinery to a character who knows only part of a fictional world.

Each step builds on explicit inputs, controlled capabilities, resources, state, and evidence. Live interaction supports discovery. Rituals preserve methods. Beings carry continuity. Laboratories characterize behavior. Directors decide which work to commission.

## Core and application

The execution foundation validates contracts, checks authority, accounts for resources, and records outcomes. Reagents connect it to resources through scoped operations. Applications give those operations meaning: a director understands commitments; a game understands fictional knowledge; a laboratory understands specimens and labels.

This division lets you build domain-specific systems while retaining common execution boundaries. A tool's contract describes its inputs, effects, authorization scopes, and evidence. Its implementation enforces those boundaries independently of the model.

## Evidence and judgment

The runtime restricts the information it supplies and the actions it permits. Model behavior still needs evaluation. A character can guess a hidden fact; a researcher can propose an incorrect interpretation; a worker can overlook an assumption.

Keep observations, computed results, and model claims distinguishable. Those distinctions make the system's outputs easier to inspect, challenge, and improve.
