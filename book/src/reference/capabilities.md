# Runtime capabilities

## Core, Language, and Essence
- **Core:** exclusive ownership before recovery, checked storage with fail-closed dispatch, atomic terminal records; auto-started daemon, JSON-RPC 2.0 over `core.sock` with length-prefixed frames, SQLite state, events stored before they can be observed. A summon running when the core died is recorded as interrupted, never as done.
- **Rituals:** offline `validate`/`compile`, explicit language version, strict schema subset and optional return schemas; versioned, content-hashed definitions with typed inputs, static reference type-checking across step outputs, loop items, expressions and child returns, embedded binding snapshots, ordered steps, bounded `each`, `if / else`, and whole-definition validation before anything runs.
- **Rituals as steps:** a child ritual is pinned at inscription, runs as its own linked summon in a fresh context, holds no more authority than its parent, and draws on its parent's essence. Cycles and excess depth fail validation.
- **Backends:** `ollama/<model>`, OpenAI-compatible `openai/<model>` (`/v1/chat/completions` with strict `json_schema` `response_format`), `anthropic/<model>` (`/v1/messages`), `mock/keyword`, and named custom providers in `config.yaml` (`providers.<name>` with `kind`, `url`, and `api_key_env`).
- **Essence:** request admission and reported token usage are shared with every ancestor. Failed backend attempts consume request essence too. Each inference request uses the earliest remaining ancestor deadline; Ollama generation is capped to the smallest remaining token budget (or a smaller explicit `num_predict`). Late or over-budget responses are recorded and rejected before dependent steps act. Exhaustion ends a batch with per-item counts and a remaining count.
- **Model lifetime:** the model stays loaded across a batch and an unload is requested when the last active summon ends.
- **Standard library:** pure `data` operations include checked arithmetic, comparisons, JSON access, strings, arrays, bounded map/filter/fold, and assertions. Scoped `file` (`read_text`, `read_json`, `stat`, `list`, `write_text`, `append_jsonl`, `delete`) and `http` (`get_text`, `get_json`, authenticated `post`/`put`/`patch`/`delete`) enforce explicit directory-root and origin grants. All ship in the binary, with no automatic grants or model calls. See [the standard library](../reference/standard-library.md).

## Authority, Fencing, and Evidence
- **Authority outside the model:** standing grants per ritual; reagents such as `mail` refuse any message their own search did not select and any destination not explicitly granted.
- **Held actions & petitions:** a write with `hold: true` (or missing authority with `--petition-missing`) is recorded as a petition with its reason and optional TTL instead of being performed. `summonr petition` shows an resource digest when supported; `petition permit` runs the action under current grants and verification and checks the resource against its recorded digest when the adapter supplies one; `petition deny` discards it.
- **Effect fencing:** non-idempotent writes are guarded in `effect_fence` (`applied`, `dispatched`, `failed`) so retries or crashes cannot silently double-apply side effects. Inspect or reconcile fences with `summonr fence list / apply / clear`.
- **User-only inputs:** an input marked `user_only` can be supplied only from the command line. Any calling agent that tries is refused, so it cannot switch off a hold or widen a scope.
- **Observed evidence:** an operation can carry a `verify` block that reads state back with a read tool and compares it. Each write is recorded as "observed by the runtime" or "reported by the tool"; a mismatch ends the item as `unverified`, never as success. A model's answer stays labeled as a model's claim.

## Rehearsal, Replay, and Drift
- **Cassettes & simulation:** `invoke ... recording PATH` saves a cassette of every model call and every read/write tool call; `replaying PATH` re-runs offline from it, authorizing tools first, computing pure `data` operations, simulating writes, and never falling back to live calls; `simulating` authorizes writes without performing them. `summonr drill R against FILE` runs scripted cases and exits `14` on failure. See [Safe building](../guides/safe-building.md).
- **Drift assays & touchstones:** `assay R against SET baseline` records a baseline account and multi-site model fingerprint; `assay R` re-runs the set and reports `within tolerance`, `drifted`, or `inconclusive` (exit `0`, `12`, `13`). A drill or assay set can name a pure **touchstone** ritual to compute expected outputs without hand labels. See [Lessons from Marain](../concepts/lessons-from-marain.md).
- **Gleaning & experiments:** `summonr glean R 10 against SET` samples real ended runs into unlabeled assay cases so the model under test never labels its own cases. `sweep`, `judge`, and `weigh` run parameterized sweeps across models, settings, and cases and rank or compare experiments.
- **Elegies:** every summon records its exact outgoing payloads, a context manifest, usage, timing, and whether output structure was enforced by the decoder.

## Identity, Provenance, and Federation
- **Identity:** every core has an Ed25519 key (`summonr identity`). Agents get their own keys (`summonr familiar new NAME`) and connect with `summonr mcp --name NAME`; requests are signed and verified, familiars see only rituals you allowed and only their own runs/petitions/fences, and runs record who asked. `summonr listen ADDR` accepts signed requests from peers (`summonr peer add`), with optional built-in `rustls` TLS (`tls: {cert, key}` in `config.yaml`). Signed, not encrypted when TLS is off. See [Identity](../concepts/identity.md).
- **Epitaphs:** every ended run gets a signed, chained, fingerprint-only epitaph (`summonr epitaph RUN`, also `receipt`). `summonr chain mark` prints a shareable snapshot and `summonr verify` checks the chain, mark, or exported/revealed file (exit `15` on failure). `summonr witness PEER` countersigns across cores and detects forks; `summonr witness tsa URL` adds RFC 3161 timestamps via `openssl`. See [Epitaphs](../concepts/epitaphs.md).
- **Pacts:** standing, signed agreements between cores (`summonr pact offer`, `agree`, `call`, `accept`, `reject`, `revise`, `end`, `export`), with optional `witnesses` for 3+ party observation and async callee push (`pact_post`) with polling fallback. A pact pins a ritual by content hash, enforces per-call and cumulative budgets, routes caller-held approvals back as `pact.decide` petitions with deadlines, separates completion from acceptance, and anchors every event in the parties' epitaph chains. See [Pacts](../concepts/pacts.md).

## Operator & Agent Surfaces
- **Workbench & Observer:** `summonr` or `summonr console` opens a persistent command prompt with live telemetry (`inspect NAME` draws a static plan). `summonr scry` and `summonr daemon` open the Ratatui workspace (`scripts/vigil.sh` opens it in a tmux popup), streaming live events over `core.sock` via `subscribe`. See [The command workbench](../guides/workbench.md) and [Watching runs](../guides/observer.md).
- **Manual summons:** `summon` (`session`), `soul`, `bind`, `imbue`, `bid`, `lethe`, and `inscribe --session` run bounded interactive sessions and compile them into saved rituals.
- **Repository chores & scoped commands:** `git`, `gh`, `trial`, and `cmd` (`cmd.list`, `cmd.read`, `cmd.write` over owner-defined `commands:` in `config.yaml` with allowlists, flag-injection defense, process-group deadlines, and optional `digest_command`), plus repository rituals in `rituals/repo/`: `land-branch`, `clean-merged`, `repo-status`, `open-pr`, `start-branch`, and `commit-work`. See [Repositories](../guides/repositories.md).
- **Agent contracts & MCP server:** `summonr mcp` (stdio) or `summonr mcp http ADDR:PORT` lets AI agents list, describe, preview, run, simulate, record/replay named cassettes, compile/drill inline, check/page/stop runs, inspect held actions and fences (`list_held_actions`, `list_fences`), and invoke saved rituals directly as projected `ritual_<name>` tools (`user_only` inputs omitted). Responses carry compact `next` guidance and `retryable: bool` error flags; up to 8 concurrent stdio calls run at once. Calling agents cannot inscribe rituals, grant authority, pick a model, reconcile fences, or approve held actions.

## Limitations & Runtime Notes

- **Total-token ceilings on backends:** Prompt tokens are known only after inference. Generation is capped and reported overruns stop dependent work, but combined prompt + output usage can still exceed the budget on a single request. Unknown token usage fails closed when a token budget applies; mock token counts are estimates, not model tokenizer measurements.
- **Built-in TLS:** Available via `tls: {cert, key}` in `config.yaml` for `summonr listen` and `summonr mcp http`.
- **Threads, not async:** The core uses OS threads and blocking I/O rather than tokio; the socket protocol does not depend on it.
- **Override propagation:** Invocation model and setting overrides propagate to child rituals unless a step pins its own model or settings. Child records show the effective inherited model (`through mock/keyword` runs the demo batch without Ollama when steps don't pin another model).
- **Execution deadlines:** Deadlines bound the inference HTTP request (connection + response-body reads) and are checked between steps and before completion. Disconnecting cannot prove a remote backend stopped computing, and OS scheduling, DNS, or native filesystem calls can delay final return.
