# Bughunt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bug-hunting rite in `examples/10-bughunt/` written only in shipped Summonr language, plus a log of every language limit hit.

**Architecture:** Pure YAML rituals and one rite. `hunt` (qwen3:4b, one angle) → `gather` (pure merge/count) gated by `batch-ready` (touchstone) → `test` (model writes a repro module, `trial` runs it in a throwaway worktree). A setup script prepares the target checkout and renders literal roots; scoring is a pure ritual against gold sets built from fix commits.

**Tech Stack:** Summonr ritual language v1, rites, `file`/`git`/`trial`/`cmd`/`data` reagents, Ollama (`qwen3:4b`, `Qwen3.6-35B-A3B`), bash + python3 for setup/gold extraction only.

**Spec:** `docs/superpowers/specs/2026-11-22-bughunt-design.md`

## Global Constraints

- No Rust changes. A missing feature becomes a `LIMITS.md` entry plus a workaround.
- master stays at `5fb6bbe`. Develop against a branch-built binary with an isolated `SUMMONR_HOME` (`~/bughunt-lab/home`), never the real home.
- Default model `ollama/qwen3:4b`, temperature 0; step-up `ollama/hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-Q4_K_M` for high/critical only.
- Literal roots use the placeholder `/absolute/path/to/target` (and `-repro`), rewritten by `setup.sh` like example 08.
- Codex hook: optional `cmd` route, off by default (`escalate: none`).

## Facts found while planning (feed LIMITS.md)

1. `requires.on.root` is a literal fixed at inscription: a ritual can't be "pointed at" a project; setup rewrites it.
2. `file.list` is not recursive; dirs to hunt are a list input.
3. `trial.run` runs the repo's single `test` command: test selection is done by registering a dedicated repo entry whose `test` is `cargo test --offline bughunt_repro`.
4. `git.worktree_add` starts only from the trunk: setup creates a `bughunt-base` branch at the target commit and registers it as that repo's trunk.
5. summonr has no `[lib]`: repro tests must be a unit-test module; the base branch commits an empty `src/bughunt_repro.rs` plus `#[cfg(test)] mod bughunt_repro;`.
6. `data.map`/`fold` bodies can't capture outer values and there is no `index_of`/numbering: findings carry a verbatim `snippet` instead of a model-counted line, and per-file context is attached in `each` bodies.
7. No range op: chunk starts are a literal list clamped against line count.
8. `each` is sequential (`parallel > 1` rejected).
9. Codex is not a model backend; only `cmd`.

## Review Focus

- Empty file / file shorter than the first chunk → hunt returns no findings for it, no failure (`data.slice` out-of-range must be clamped first).
- Model returns an empty findings list for every chunk → gather count 0, gate rejects, rite stops cleanly.
- Repro test fails to compile → verdict `untestable`, worktree restored clean so the next finding still runs.
- Trial tail >900 bytes truncates compiler errors → verdict still derived from `passed` plus a marker string the repro prints, never from the tail alone.
- Same snippet reported by two angles → gather dedupes to one.

### Task 2: hunt ritual + drill

**Files:** `examples/10-bughunt/hunt.yaml`, `hunt.drill.yaml`.

Inputs: `dirs: [string]` (relative to root), `angle: string`, `max_files: integer = 40`, `chunk: integer = 150`, `starts: [integer]` default `[0,150,…,2850]`.
Output: `{angle, files: integer, findings: [{file, start, kind, severity, confidence, claim, trigger, snippet}]}`.
Schema per model call: `{findings: [{kind: [bug, bypass], severity: [low, medium, high, critical], confidence: number 0..1, claim: string≤300, trigger: string≤300, snippet: string≤200}]}`.

- [ ] Drill cases: one file with one scripted finding → result has `file` and `start` attached; empty file → zero findings, returned; non-.rs file filtered out.
- [ ] Run drill: FAIL (ritual missing). Write ritual. Run drill: PASS.
- [ ] Live smoke: `dirs: [src/reagents]`, angle "authority bypass", `max_files: 2` on qwen3:4b; record requests/tokens/time.
- [ ] Commit.

### Task 3: gather + batch-ready + drills

**Files:** `gather.yaml`, `batch-ready.yaml`, drills.

`gather` inputs `hunts: list` (hunt outputs), `min_batch: integer = 5`, `floor: number = 0.3`; returns `{findings (deduped on file+snippet+kind, ≥floor), count, min_batch, pass}`. `batch-ready` input `output: object`; returns `{pass: output.pass}`.

- [ ] Drills: duplicates across two hunts collapse; below-floor dropped; count < min_batch → `pass: false`.
- [ ] Commit.

### Task 4: test ritual + drill

**Files:** `test.yaml`, `test.drill.yaml`.

Inputs `findings: list`, `escalate: [none, codex] = none`. Per finding (`each`, `on_failure: continue`): read file context (lines `start..start+chunk`) from target root → model (if/else by severity) writes `{test_body: string}` (a `#[test]` fn that `panic!("BUGHUNT-CONFIRMED")`s only when the bug shows) → `file.write_text` to `src/bughunt_repro.rs` in the repro worktree → `trial.run` → restore empty file → verdict: `passed=false` and tail contains `BUGHUNT-CONFIRMED` → `confirmed`; `passed=true` → `refuted`; else `untestable`. Worktree added before the loop, removed after.
Output: `{results: [{…finding, verdict, test_body, tail}], counts}`.

- [ ] Drill (mock model, `simulating`): verdict mapping for the three branches.
- [ ] Live: one hand-made true finding confirmed end to end.
- [ ] Commit.
