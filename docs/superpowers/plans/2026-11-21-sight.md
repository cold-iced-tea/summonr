# Sight Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let rituals read PNG/JPEG/WebP images into handles with a `sight` reagent and send them to vision models through `images:` on model steps.

**Architecture:** `sight.read_image` reuses the `file` reagent's descriptor-relative path code, returns a metadata-only handle, and records an issue key in the run's existing selection set (so children, petitions and `adopt`-based replay/revive inherit it). Model steps resolve `images:` references, refuse unissued handles, re-read and verify bytes, and pass `ImagePart`s on `ChatReq`. Backends build two payload forms: inline (sent) and placeholder (recorded everywhere).

**Tech Stack:** Rust 2021, serde/serde_json, `base64` 0.22 (existing), `sha2` (existing), optional `imagesize` 0.14.

**Spec:** `docs/superpowers/specs/2026-11-21-sight-design.md`

## Global Constraints

- Accepted types by magic bytes only: `image/png`, `image/jpeg`, `image/webp` (animated WebP refused). GIF and anything else refused.
- Defaults: 10 MiB (10,485,760 bytes) per image, 8 images per step. `config.yaml` `sight: {max_bytes, max_per_step}` may only lower them.
- No image bytes or base64 in elegies, epitaphs, cassettes, events, MCP results, TUI.
- A model step with no `images` produces byte-identical payloads and request hashes to today.
- Build/tests must pass offline: `cargo test --offline`, `cargo clippy --offline -- -D warnings`, `python3 scripts/check_offline.py`. CI parity: `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1`.
- Do not use the full `image` crate. Do not touch essence pricing (another branch, `feat/monetary-budgets`, owns it).
- Do not run `scripts/generate_definition_schema.py` to regenerate `schemas/ritual-v1.schema.json` (it drops `defs/$defs`); edit the schema by hand.
- Commits: end messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit via the `commit-work` ritual (repo `summonr`, branch `feat/sight`) or plain git in the worktree.

## Review Focus

1. A handle-shaped object arriving from inputs, MCP arguments or model output must be refused by the model step (Task 4 test `forged_handle_from_input_is_refused`).
2. File replaced, edited or swapped for a symlink between `read_image` and the model step → step fails "stale image", nothing dispatched (Task 4 `changed_image_is_stale_and_not_sent`, `symlinked_image_is_refused_at_send`).
3. A ritual with images drilled or replayed on `mock` with no vision model available must work and not contact Ollama (Task 4 `mock_drill_with_images_needs_no_backend`).
4. A checkpointed run revived after the image changed must not send the new bytes (Task 5 `revive_rechecks_image_digest`).
5. Existing cassettes and non-image payloads must still match after the `ChatReq` change (Task 3 `no_image_payloads_and_hashes_unchanged`).

**Interfaces:**
- Consumes: `Images` (Task 2), `issue_key`, `load_verified`, `DEFAULT_*` (Task 1), `ImagePart`, `supports_images` (Task 3).
- Produces: `pub struct SightConfig { pub max_bytes: Option<u64>, pub max_per_step: Option<usize> }`; `Config::sight_limits(&self) -> (u64, usize)` returning `min(configured, default)`. A configured value above the default is a config load error ("sight limits can only be lowered").
- Behaviour in `fn model`, after rendering the prompt and before `admit_request`:
  1. Resolve `m.images` with `ritual::render_value`; flatten `One(list)`/`Many`; anything not an object with `kind == "image"` → `Fail::Invalid("step {sid}: images entry is not an image handle")`.
  2. Count > max_per_step → `Fail::Invalid`.
  3. Each handle's `issue_key` must be in `self.selected` → else `Fail::Denied("step {sid}: image was not read by sight in this run")`.
  4. `load_verified(handle, max_bytes)` → `ImagePart`.
  5. If `!self.io.offline()` and images non-empty: `backend::supports_images(&base_url, &model)` → `Fail::Failed` on refusal.
  6. Manifest gets `{"part":"image","sha256","path","mime","width","height","bytes"}` per image.
  All of 1–5 happen before `admit_request()`, so a refused step spends no request.
